## First unexpected failure

The Running menu offered neither Enable subscription nor Rotate Client Identity. View details reported:

`Subscription enablement check: Shared Certbot admission`

A repeated read-only check of the unchanged packaged menu failed the assertion that `Enable subscription` was present. Test mutations stopped at this failure; only read-only diagnosis and separate safety cleanup followed.

Diagnosis found:

- `pgrep --exact certbot` returned `1`: no matching process.
- `snap.certbot.renew.service` was inactive/dead, with `MainPID=0` and `Result=success`; its timer was waiting.
- No Certbot/Let's Encrypt/SBXR locks appeared in the `lslocks` observation.
- All three `.certbot.lock` files were absent.
- `/var/log` was a directory owned by UID `0`, GID `104` (`root:syslog`), mode `0775`.
- `/var/log/letsencrypt` was root-owned mode `0700`; the other inspected ancestors were root-owned mode `0755`.

The packaged source's `PreflightSubscription` calls `safeParents` for `/var/log/letsencrypt/.certbot.lock`. `safeParents` rejects group- or other-writable ancestors. `/var/log` therefore makes `RenewalIdle.Accepted` false even though the process/lock observations are idle. `subscriptionAdmission` renders that failure as Shared Certbot admission with a wait-for-work correction. The same false admission removes Rotate Client Identity from the menu. Waiting for Certbot does not resolve the observed parent-permission condition.

No directory permissions, safety check, package version, or executable bytes were changed to bypass this refusal. No certificate issuance, subscription enablement, or client credential disclosure was performed. The Certbot version change is an observed environment difference, not the demonstrated cause of this refusal.
