# Pasteable installation and destructive reclamation

SBXR provides one interactive Pasteable Install Command for Ubuntu 24.04 on `linux/amd64` and `linux/arm64`. GitHub's moving stable asset URL selects an immutable `install.sh` that embeds one exact repository, tag, commit, version, sequence, supported architecture set, and six expected asset names. The exact release has six assets: `install.sh`, `release-index.json`, and the application and component archives for both architectures. The bootstrap downloads and verifies the co-released index through that immutable release. It cannot embed the index digest because the index binds the complete `install.sh` bytes. The bootstrap trusts its first download through GitHub HTTPS, repairs only the fixed Ubuntu launch prerequisites, prints fixed safe stages and refusal codes, cleans its Owner-only temporary directory, and launches the authenticated SBXR executable as the original non-root Owner. It never receives Cloudflare authority or performs Destructive Reclamation. This accepts a weaker initial remote-script trust boundary and pre-Plan prerequisite `sudo` in exchange for a short installation command on an otherwise ordinary host.

A Not installed host may be a Clean VPS or a Reclaimable VPS. SBXR freshly inventories every local and Cloudflare conflict, shows the exact effects in one secret-safe Plan, requires the Owner to enter `RECLAIM THIS VPS`, obtains `sudo`, writes and syncs protected recovery authority, and records **Irreversible reclamation started** before its first destructive effect. The Owner may leave before that checkpoint. After it, cancellation and rollback are unavailable: failure, terminal loss, process death, or reboot enters forward-only **Recovery Required** at the exact last proven checkpoint and continues until the complete installation is proven **Managed** with no unfinished journal.

Destructive Reclamation may purge exact reviewed conflicting packages without autoremove; replace inbound firewall policy while preserving the current SSH connection, reviewed SSH port, outbound traffic, loopback, established traffic, and required IPv6 behaviour; delete exact conflicting Cloudflare resources by freshly proved identifiers; remove Docker while preserving its images, volumes, Compose files, bind mounts, and application data; and preserve unrelated website files, databases, certificates, logs, homes, backups, and other data. It may stop an unknown conflicting process and delete its exact unchanged regular executable or a script proved through one fixed unambiguous interpreter form. It must refuse protected host foundations, symlinks, mounts, shared hard links, ambiguous wrappers, and unproved targets. If the exact file belongs to an otherwise unsupported package, SBXR may leave that package damaged, place it on Ubuntu's native package hold, show the missed-security-update and no-rollback consequences in the Plan and Diagnostics, and remove the hold without repairing the package during Complete removal.

Complete removal deletes only SBXR-owned resources and package holds; it never reconstructs reclaimed software or firewall state. The ordinary README command targets only the newest stable release and remains marked unavailable until a six-asset stable release is published and its URL is verified. Release `v1.0.6` is the current identity that passed the gate and activated the command. For this installer path, automated Module, Seam, Integrated, hostile, process-death, and reboot tests are sufficient for stable qualification; a live disposable-VPS run and client-device acceptance are not required unless the release independently changes a client-facing surface. This deliberately trades real-host evidence and rollback for an easier, more forceful installation experience on both Clean and valued Reclaimable VPS hosts.

This decision supersedes ADR-0006 wherever ADR-0006 admits only a Clean VPS, refuses competing firewall managers or conflicting provider resources, or requires rollback for installation preflight. Its exact implementation and qualification remain gated by the approved issue tree under umbrella issue #143.
