# Connection Profiles

Connection Profiles owns the six server-side connection choices. Issues #100–#107 deliver VLESS REALITY Vision, VLESS XHTTP, independent VLESS WebSocket, Hysteria2, TUIC, AnyTLS, their exact truthful registry, and the coordinated lifecycle through `View`, `Plan`, and `Apply`.

On a fresh conflict, Network Policy may supply one reviewed bind-proven alternative for each preferred port. The registry carries that exact selection through both native configurations, exposure, health, State service material, Cloudflare route health, and publication. A committed port is stable: a later conflict stops in Correction Flow and never silently selects another port.

Credential replacement is either one selected profile or all six profiles in one `Rotation` Change Set. Repair is forward-only from a fresh System Changes proof for the exact current State lineage; caller-made or stale repair requests are refused. Candidate core updates must accept the complete six-profile configuration and then restart automated, live, and Owner acceptance at `Pending`; native validation never replaces known-good evidence.

`Live Profile Check` runs only after a fresh `Managed` observation. It consumes one universal subscription URL once and returns only per-profile authenticated uplink/downlink booleans. It deliberately cannot render or retain the URL, client address, destination, counters, logs, or traffic history.

`View` fails closed unless the selected target is `443/TCP`, the accepted name agrees, `xray tls ping` and normal TLS name verification pass, and the target is neither Cloudflare-fronted nor Apple or iCloud. On an existing Managed installation it also requires the fixed root `xray.service`, exact systemd containment, exact protocol-aware listener, root:`root` `/etc/sbxr/xray/config.json`, and only the `CAP_NET_BIND_SERVICE` capability required by a selected port below `1024`.

`Plan` generates one complete Xray `v26.3.27` configuration using VLESS, RAW, REALITY, `xtls-rprx-vision`, and bounded fallback upload and download. It passes those exact bytes to `xray run -test -config stdin:` before producing a deterministic, secret-safe, one-use Plan. State accepts those exact reviewed bytes through the Plan's short-lived secret reader and stores them as the protected prepared `xray.service` artifact. `Apply` contributes one reversible prepared-configuration step and Required configuration, listener, and service gates before publication, plus exact configuration validation after publication; it never mutates the host or publishes Desired State directly.

The REALITY UUID, X25519 private key, public key, and short ID are checked as one matching credential set. State may supply the protected UUID, private key, and short ID only through its short-lived Connection Profiles secret reader. Interface results, findings, Plan rendering, native errors, and typed observations never contain those values or raw generated configuration.

VLESS XHTTP uses an independent UUID and independently generated 32-byte path. Its server behavior is fixed to `packet-up`; client `mode=auto`, `stream-up`, and `stream-one` are not server settings. Xray listens without local TLS only on `127.0.0.1:11080/TCP`. Cloudflare Tunnel owns edge publication and supplies a typed result binding the selected hostname to `http://127.0.0.1:11080`; Connection Profiles refuses a missing, unhealthy, or mismatched binding.

An existing Managed installation is Healthy only when the complete root:`root` Xray configuration passes the installed native validator, `xray.service` runs as root with `NoNewPrivileges=true`, `ProtectHome=true`, and `ProtectSystem=strict`, the listener is exactly loopback-only, and the typed Cloudflare XHTTP route agrees. The XHTTP Plan validates the complete REALITY-plus-XHTTP configuration with Xray `v26.3.27`, binds the exact UUID, path, route observation, State lineage, and prepared bytes, and contributes reversible activation plus Required configuration, listener, and service gates before publication, plus exact configuration validation after publication.

VLESS WebSocket is an independent compatibility profile, not an XHTTP substitute. It has its own UUID, independently generated 32-byte path, public hostname, Cloudflare route, health row, and acceptance rows. Its destination hostname, edge TLS name, HTTP Host, protected active path, and typed route must agree. Xray listens without local TLS only on `127.0.0.1:11081/TCP`; the Ubuntu observer refuses multiple listeners and compares the protected active WebSocket Host and path without returning either value.

The WebSocket Plan validates one complete REALITY-plus-XHTTP-plus-WebSocket configuration with Xray `v26.3.27`. It binds the exact independent credentials, paths, hostnames, typed route observations, State lineage, and prepared bytes, then contributes one reversible activation step and Required configuration, listener, and service gates before publication, plus exact configuration validation after publication. Cloudflare owns edge publication, and Subscription Publication owns client rendering and maintained-client compatibility.

Hysteria2 is the first sing-box profile. It uses sing-box `1.13.16`, one independently generated 32-byte password, public `443/UDP`, required TLS, and the shared active Direct TLS pair at `/var/lib/sbxr/certificates/domain/current`. Its selected VPS address is the client destination; the exact reviewed Direct TLS Hostname is the normally verified TLS name. The same typed Direct TLS contribution binds that hostname to Hysteria2, TUIC, and AnyTLS, while Network Policy proves that REALITY `443/TCP` and Hysteria2 `443/UDP` intentionally coexist without a protocol collision.

Obfuscation is absent, no Hysteria2 zero-RTT setting exists, and unauthenticated traffic receives a fixed HTTP/3 `404 Not Found` response. The complete sing-box configuration uses `/etc/sbxr/sing-box/config.json`, `0755` root:`root` directories, and a `0644` root:`root` file. `sing-box.service` runs as root with `NoNewPrivileges=true`, `ProtectHome=true`, `ProtectSystem=strict`, and only `CAP_NET_BIND_SERVICE` for the privileged listener. Healthy also requires native configuration validity, exact active-field agreement, one public UDP listener, the active certificate matching the reviewed hostname, and bounded authenticated TCP and UDP server probes.

TUIC is the second sing-box profile. It uses an independent UUID and 32-byte password, public `8443/UDP`, required normal TLS verification with the selected VPS address and exact Direct TLS Hostname, `zero_rtt_handshake: false`, and `congestion_control: cubic`. BBR is not enabled. “TUIC” is the product term; a client may add “v5” only when its own representation requires that label.

The TUIC Plan validates the unchanged complete three-profile Xray configuration and one complete Hysteria2-plus-TUIC sing-box configuration. One opaque binding covers both exact protected artifacts. Healthy requires the exact root-runtime active configuration, native validity, public `8443/UDP`, the contained root service, the typed shared Direct TLS identity, and bounded authenticated TCP and UDP server probes. Apply contributes one reversible activation step and Required configuration, listener, service, and server-function gates; rollback restores the prior complete artifacts. Subscription Publication still owns client rendering and outside maintained-client compatibility.

AnyTLS is the third sing-box profile. It requires sing-box `1.12.0` or later and is initially qualified only with `1.13.16`. It uses an independent 32-byte password, public `9443/TCP`, the selected VPS address, required normal TLS verification with the exact Direct TLS Hostname, and the same protected active certificate pair. SBXR deliberately omits `padding_scheme`, so the installed qualified sing-box core owns its maintained default; fields from an uninstalled later release are refused by the pinned native validator.

The AnyTLS Plan validates the unchanged complete three-profile Xray configuration and one complete Hysteria2-plus-TUIC-plus-AnyTLS sing-box configuration before mutation. Healthy requires exact active agreement for all three sing-box profiles, native validity, one public `9443/TCP` listener, the contained root service, the typed shared Direct TLS identity, and a bounded authenticated TCP server probe. Apply uses the shared reversible activation step and Required configuration, listener, service, and server-function gates; rollback restores the prior complete artifacts. Subscription Publication still owns client rendering and outside maintained-client compatibility.

The canonical registry contains exactly the three named VLESS profiles, Hysteria2, TUIC, and AnyTLS in that order. Fresh setup generates all six independent credential sets, independently generates the XHTTP and WebSocket paths, and enables every profile. `ViewRegistry` returns safe credential readiness, selected and observed listeners, hostnames, qualified versions, desired enablement, and typed health. No seventh profile can enter the fixed typed request or result.

A disabled profile keeps its validated setting and credential in Desired State but is reported as `Disabled`, not `Failed`. Its Network Policy exposure and Cloudflare route material are absent, its native inbound is omitted, and its canonical `PublicationSource` contains one exact omission fact instead of a client representation. `PublicationSource` supplies typed server and client facts to Subscription Publication; it does not render a URI, YAML, JSON, QR payload, client label, or compatibility claim.

`PlanRegistry` accepts exactly one enablement change, refuses changed credentials or settings and multiple toggles, validates the complete remaining Xray and sing-box configurations through the pinned native cores before mutation, and binds the fresh Network Policy revision/digest plus the exact exposure and publication result. A core with no enabled profile receives a native-valid empty-inbound configuration. Re-enable requires a separate reviewed forward Plan and reuses the preserved setting and credential. Both directions use the same reversible prepared-configuration step; rollback restores the prior complete Xray and sing-box artifacts. Failed registry health always returns all six fixed rows and no publication authority; disabling the last privileged listener also requires the service capability set to become empty.
