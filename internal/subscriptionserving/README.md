# Subscription Serving

Subscription Serving is the isolated public HTTPS runtime for the active immutable subscription artifacts. Its production entry point is the private `sbxr private subscription-serve` mode used only by `sbxr-subscription.service`.

The exact `/base64`, `/raw`, `/v2rayn`, `/shadowrocket`, `/karing`, `/mihomo`, and `/sing-box` suffixes return the corresponding active published bytes. Explicit suffixes always win over `User-Agent`. The unsuffixed route recognizes conservative case-insensitive v2rayN, Mihomo/Clash Meta, and sing-box format hints; unknown or conflicting hints return base64. Only the unsuffixed route sends `Vary: User-Agent`. Every success names the selected format in `X-SBXR-Representation`; Karing and sing-box also disclose `X-SBXR-Omitted-Profile: vless-xhttp`. Shadowrocket remains labeled as a candidate rather than Owner-accepted.

URI and base64 bodies use `text/plain; charset=utf-8`, Karing and sing-box use `application/json`, and Mihomo uses `application/yaml`. Every success also sends `Cache-Control: private, no-store`, `X-Content-Type-Options: nosniff`, and `Referrer-Policy: no-referrer`. Every other token, route, suffix, query, encoded path, or method shape receives the same plain `404`. There is no `/<token>` alias, redirect, index, login, HTTP listener, insecure TLS, self-signed fallback, Cloudflare route, or domain fallback.

The public boundary has fixed, non-configurable limits: 60 parsed requests per one-minute window, including hostile requests while preserving their plain `404`, eight simultaneous TCP/TLS connections, 16 KiB of request headers, no accepted request body with a 1 KiB defensive body reader, 1 MiB per served representation, and 64 KiB for artifact metadata. TLS handshake and header-read timeouts are five seconds; request-read and response-write timeouts are ten seconds; total handler work is limited to 15 seconds; an idle connection closes after 30 seconds. These are service rules, not Owner settings, accounts, per-device quotas, billing, usage history, or client identity. User-Agent and client IP are not rate-limit identities and are not retained.

The production listener binds only the selected IP family and exact selected IP at `10443/TCP`. `Serve` starts only after normal trust-chain, validity, private-key, and exact IP-SAN checks succeed. The controlled `NewAt` constructor replaces only the host root, service ownership, trust roots, and clock for full-TLS Seam Verification; production uses fixed paths and system trust roots.

The runtime reads only:

- `/var/lib/sbxr/subscriptions/current/`, containing `serving.json` with the one minimum authorization fact, selected address, fixed port, and fixed certificate pointer beside the complete active immutable artifact set; and
- `/var/lib/sbxr/certificates/ip/current/`, containing the active certificate pair.

Subscription Publication receives the State-prepared `subscription.json` through the existing System Changes transaction, validates it as protected regular input, writes it as `serving.json` beside the eight Publication files, and atomically exchanges that complete nine-file generation. Serving opens `current/` once per refresh and reads every file through that one directory handle. Concurrent requests therefore use either the complete prior authorization-and-body snapshot or the complete candidate; a missing, partial, unsafe, or invalid candidate leaves the in-memory prior snapshot active. Token rotation stops later downloads at the old path only when the new token and complete candidate bodies become readable together. A deliberate profile enablement or disablement remains the exact Publication-produced omission and body set.

The complete active snapshot uses the approved `root:root` `0755`/`0644` boundary. Certificate Lifecycle separately supplies one narrowly validated relative `current` pointer to a `root:root` `0755` versioned set with `0644` files. Serving refreshes the certificate before each TLS handshake only after the complete pair passes normal verification; activation failure keeps the previous proven in-memory HTTPS state while the owning Change Set restores the prior pointer and re-proves it. The owning Modules prove every host parent has its exact non-writable mode. Any other symbolic link, extra or missing file, non-regular file, wrong final ownership, wrong final mode, oversized file, malformed base64, invalid configuration, or invalid certificate input stops startup or is refused as a runtime candidate. Serving also verifies every named body against its Publication-recorded SHA-256, then requires the exact published representation list, completed metadata, valid omission/count agreement, byte-identical base64/v2rayN/Shadowrocket artifacts, exact base64-to-raw decoding, byte-identical Karing/sing-box JSON, and a non-empty Mihomo artifact. Inactive publication generations remain non-traversable outside root at `0700`; native certificate candidates remain `0700`/`0600` behind Certificate Lifecycle. Neither is readable through the service namespace.

The systemd unit runs as `root:root`, exposes no capabilities or writable SBXR path, disables core dumps, and starts from an otherwise empty read-only filesystem containing only the executable, service configuration, active artifacts, active certificate pointer, and public trust bundle. The Ubuntu Adapter reads the effective unit, `User`, `Group`, active process identity, and the one `10443/TCP` listener. The Subscription Serving Interface accepts those typed facts only when the effective unit is byte-identical to the fixed unit, the listener belongs to the active process and selected address, and the active immutable files and certificate pair also pass. Desired State, transaction evidence, Certbot material, Cloudflare material, and arbitrary VPS content are absent from that namespace. The package imports no other product Module and offers no file, command, firewall, service, certificate, publication, renderer, rollback, recovery, or VPS mutation operation. Public access logs, traffic history, telemetry, crash reporting, response-body logging, token logging, and raw external errors are absent.

Serving owns no Plan, Change Set, rollback copy, recovery journal, artifact renderer, validator, publisher, or historical restore. Subscription Publication, Certificate Lifecycle, State, and System Changes retain those existing responsibilities. Required pre-publication checks, one Desired State publication, post-publication agreement, durable `Complete`, rollback, restart inspection, and Recovery Required therefore stay in the one normal Change Set.

`Failure` carries the stable secret-safe codes `SUBSCRIPTION-SERVING-ARTIFACT`, `SUBSCRIPTION-SERVING-CERTIFICATE`, `SUBSCRIPTION-SERVING-LISTENER`, and `SUBSCRIPTION-SERVING-RUNTIME`. `Health` re-validates the active candidate without changing the proven in-memory state, so the normal Change Set gate can reject and roll back a bad transition while existing HTTPS requests keep using the prior state. `Result` converts a successful check to `Healthy`, a typed refusal to `Failed`, and an unexpected untyped failure to `Unknown`. Hostile requests, rate refusals, TLS errors, HTTP errors, filesystem errors, and listener errors never pass raw text through.
